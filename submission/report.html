B. Methodology

Brand assumptions

VÉRAN is a fictional, all-gender contemporary designer fashion house offering ready-to-wear, footwear, bags and accessories. Its experimental design language includes unexpected proportions and asymmetry. Typical featured prices are RMB 3,000–8,000; case-specific product facts are authoritative. The advisor should sound warm, concise and natural in Chinese, without formal luxury clichés or sales pressure.

Tool design

Each request combines the shared brand and factual rules, exactly one scenario module, and supplied case facts. The model returns structured JSON: three messages and a separate advisor note for eligible cases. Missing facts stay unknown. Explicit opt-outs use a no-send branch. Evaluation expectations are excluded from the generation input. A small validator checks status, count and Chinese text; it does not establish truthfulness or naturalness. Advisors review drafts before use; the tool sends nothing.

Test design and iteration

The 50 concise fictional cases cover greetings (8), recommendations (9), aftercare (8), reactivation (8), invitations (8) and price objections (9). They vary stated preferences, relationship, known facts and common concerns: unknown discounts, complaints, incomplete event details, latest preferences and declined purchases. Six cases were used for the initial review. One consolidated language revision produced v2.1, which was then run on all 50 cases, including those six. The 50-case results therefore are not an untouched independent test set.

What good and unacceptable mean

Good messages are grounded in supplied facts, respond to the latest need, read like short friendly WeChat messages, and provide three useful choices. Unacceptable outputs invent consequential facts or promises, violate explicit contact limits, give unsupported care instructions, miss the actual question, or fail to provide the required candidates. Small style or variation problems are marked “Needs edit”.

Review uses four pass/issue checks per group: facts and boundaries; scenario and context; Chinese expression; three useful choices. A group passes only if all four pass. Serious factual, boundary or task failures are labeled “Fail”. Technical execution failures are recorded separately and never counted as passes. The reviewer is Codex-assisted; no independent advisor panel or customer outcome study was conducted.

Bonus: architecture

Advisor input / local form→Shared rules + one scenario + known facts→Codex CLI / model→JSON validation→3 Chinese drafts + separate note→Advisor review

Exact input, assembled prompt, versions, hashes, output and execution metadata are retained per run. The no-send and insufficient-information statuses return an advisor note rather than customer messages.

Using the tool

Double-click the tool launcher in the project root. The local form accepts new inputs, displays three Chinese candidates and a separate advisor note, and lets the advisor copy or download results. The submission folder contains the report and supporting material; the code folder contains the implementation. New generation requires Python, an authenticated Codex CLI and network access.

Alternatively, run these commands from the code folder:

python -m veran_advisor.demo
python -m veran_advisor.generate data/examples/case_001.json
python -m veran_advisor.generate data/test_cases.json --case-id P01
python -m scripts.batch_generate

The code and portable run evidence remain in the project directory. This report opens locally without an account; generating fresh results requires Python and the authenticated Codex CLI. No messages are sent and nothing has been published.
